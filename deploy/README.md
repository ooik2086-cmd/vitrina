# VITRINA-ны серверге орнату

Бұл нұсқаулық таза Ubuntu 22.04 не 24.04 серверіне арналған. 2 ядро мен 4 ГБ жад жеткілікті. Серверде бәрі Docker-де жүреді:

| Қызмет | Не істейді |
|---|---|
| `caddy` | Интернетке ашық жалғыз қызмет (80 және 443 порттары). Доменге HTTPS сертификатын Let's Encrypt-тен өзі алып, өзі жаңартады. http сұрауларын https-ке бұрады. |
| `api` | Сервер, 2 процесс, бір ядроға бір процесс. Жаңа нұсқа іске қосылғанда дерекқорды өзі жаңартады (`alembic upgrade head`). |
| `photos` | Фотолардың фонын алады, кіші көшірмелер мен іздеу векторын жасайды. Ең көбі 1,7 ГБ жад алады (өлшенген), шегі 2,5 ГБ. Процессорды API-ге бірінші береді. |
| `jobs` | Әр 5 минут сайын уақытқа байланысты жұмыстарды орындайды: төленбеген тапсырысты жабу, ақшаны қайтару, тапсырысты өзі аяқтау, еске салу. 15 минут бойы бірде-бір өту сәтті болмаса, `unhealthy` болады. |
| `db` | PostgreSQL 16. Порты ашық емес, оған тек ішкі қызметтер жетеді. |

Фотолар мен жабық файлдар (түбіртектер, дау дәлелдері) екі жолдың бірімен сақталады. Оны `.env`-тегі `VITRINA_STORAGE` жолы таңдайды:
- **`disk`** (`setup.sh` осыны жазады): сервердің өз дискінде, Docker томдарында (`media` және `private`). Фотоларды Caddy `https://ДОМЕН/media/...` мекенжайынан береді. S3 керек емес, сондықтан сайтты бірден іске қосуға болады. Бірақ сервер жоғалса, фотолар да жоғалады. Сондықтан түнгі көшірмені серверден тыс жерге көшіріп тұру керек (төменде).
- **`s3`**: деректері Қазақстанда сақталатын S3-үйлесімді сақтау орнында. Телефондар фотоларды тікелей сол жерден жүктейді.

## Алдын ала керегі
1. **Сервер**: Ubuntu 22.04 не 24.04, root ретінде SSH арқылы кіру.
2. **Домен**: A жазбасы сервердің IP мекенжайына бағытталуы керек, мысалы `vitrina.kz → 203.0.113.10`.
   - Сертификат тек содан кейін алынады.
   - Тіркеушінің «тұрақ» бетіне апаратын AAAA жазбасы болса, оны өшіріңіз.
3. **Диск**: фотолар дискте сақталса (`disk`), кемінде 80 ГБ диск алыңыз.
   - Бағалау (өлшенбеген): 360° тауарға фото, кесілген нұсқалары және кіші көшірмелерімен бірге 20–40 МБ, қарапайым тауарға 3–8 МБ.
   - Түнгі көшірме фотолардың екінші данасын сол дискке жазады, сондықтан орын екі есе кетеді.
   - Диск 90%-дан толса, түнгі көшірме қатемен аяқталады.
   - **S3 (тек `s3` таңдалса).** Деректері Қазақстанда сақталатын провайдер болуы керек.
     - Көшірмелерде телефон нөмірлері мен мекенжайлар бар, жабық бакетте түбіртектер тұр. Жеке деректер туралы заң оларды Қазақстанда сақтауды талап етеді. Таңдауды заңгермен тексеріңіз. Бұл `disk` үшін де маңызды: сервердің өзі Қазақстанда болуы керек.
     - Бір endpoint, бір кілт жұбы және үш бакет керек: фотолар (**ашық оқу** рұқсатымен), түбіртектер мен дау дәлелдері (ашық **емес**), дерекқордың түнгі көшірмелері (ашық **емес**).
     - Провайдер мүмкіндік берсе, көшірме бакетіне нұсқаларды сақтауды (versioning) не жоюға тыйымды (object lock) және тек сол бакетке арналған бөлек кілтті қосыңыз.
     - `.env`-те `VITRINA_STORAGE=s3` қойып, S3 жолдарын толтырыңыз, ал `VITRINA_PUBLIC_MEDIA_URL` жолына фотолар бакетінің ашық мекенжайын жазыңыз.
     - `disk` режимінде тек көшірме бакетін қосуға болады. Сонда дерекқор көшірмесі әр түні серверден тыс жерге кетеді, бірақ фотолар кетпейді.
4. **Let's Encrypt үшін email**: сертификат туралы хаттар соған келеді.
5. **Mobizon аккаунты (mobizon.kz)**: кіру коды SMS-пен осы қызмет арқылы жіберіледі.
   - «Настройки API» бөлімінде «Включить доступ к API» басып, кілтті алыңыз. Сол жерде тек сервердің IP мекенжайына рұқсат беріңіз.
   - Әр SMS ақылы. Балансты толтырып тұрыңыз, әйтпесе ешкім кіре алмайды (қосымша «SMS жіберілмеді» дейді).
   - Код тек Қазақстан нөмірлеріне (+7 6xx, +7 7xx) жіберіледі. Mobizon-да басқа елдерге жіберуді өшіріп қойсаңыз, тағы бір қорғаныс болады.
   - Жіберуші атауын (мысалы `VITRINA`) Mobizon-да тіркеп, бекітілгеннен кейін `.env`-тегі `VITRINA_MOBIZON_FROM` жолына жазуға болады. Бос болса, Mobizon-ның ортақ атауы қолданылады.
   - Кілтті чатқа не хатқа жібермеңіз: ол тек сервердегі `.env` файлында тұрады.
6. **Сайтты кім жүргізеді**: ЖК не ЖШС атауы мен ЖСН/БСН (`VITRINA_OPERATOR`) және адамдар жеке деректер туралы жазатын email не телефон (`VITRINA_SUPPORT_CONTACT`). Екеуі `https://ДОМЕН/privacy` және `https://ДОМЕН/delete-account` беттерінде ашық көрсетіледі. Бұл беттердің мәтіні алдын ала нұсқа: оны заңгер тексеруі керек (`backend/vitrina_api/legal.py`).

## Орнату
```sh
ssh root@SERVER_IP
apt-get update && apt-get install -y git
git clone -b claude/initial-code https://github.com/ooik2086-cmd/vitrina /opt/vitrina
sh /opt/vitrina/deploy/setup.sh vitrina.kz you@example.kz
```
Бірінші іске қосуда скрипт мыналарды жасайды:
- Docker-ді орнатады;
- брандмауэрді қосады: тек ssh, 80 және 443 порттары ашық;
- 2 ГБ swap қосады;
- қауіпсіздік жаңартуларын автоматты түрде қосады;
- уақыт белдеуін Қазақстан уақытына (UTC+5) қояды;
- `deploy/.env` файлын жаңа кездейсоқ құпия кілттермен жазады;
- `deploy/backup.env` файлын жазады.

Содан кейін скрипт тоқтап, қай жолдарды толтыру керегін айтады. `disk` режимінде бұл `VITRINA_MOBIZON_API_KEY`, `VITRINA_OPERATOR` және `VITRINA_SUPPORT_CONTACT`, ал `s3` режимінде S3 жолдары да:
```sh
nano /opt/vitrina/deploy/.env
nano /opt/vitrina/deploy/backup.env     # міндетті емес: көшірме бакетінің бөлек кілті, ескерту мекенжайы
sh /opt/vitrina/deploy/setup.sh
```
Екінші іске қосуда скрипт мыналарды жасайды:
1. Доменнің DNS жазбасын тексереді.
2. Бәрін іске қосады.
3. Сақтау орнын тексереді. `disk` режимінде екі қалтаға файл жазып, кері оқып, өшіреді. `s3` режимінде үш бакетке солай жасап, кілттердің дұрыстығын, фотолар бакетінің ашық екенін және қалған екеуінің жабық екенін тексереді.
4. Бірінші көшірмені жасайды.
5. Түнгі көшірмені баптайды.
6. `https://ДОМЕН/api/v1/health` мекенжайын тексереді. Жауап `{"ok":true}` болуы керек.

Бір қате болса, скрипт не түзету керегін айтып тоқтайды.

- **DNS кешіксе:** скрипт «does not answer yet» деп жазады. A жазбасы дұрыс болғаннан кейін `docker compose -f /opt/vitrina/deploy/compose.yml restart caddy` командасын орындаңыз, сонда Caddy сертификатты бірден сұрайды. Әйтпесе ол сағаттап күтуі мүмкін.
- **Доменді ауыстыру:** скрипт бар `.env` файлын ешқашан қайта жазбайды. Алдымен мынаны ескеріңіз: қосымшаның ішінде сервер мекенжайы жазылған, сондықтан домен ауысқанда телефондағы ескі нұсқалар жұмысын тоқтатады. Доменді тек қажет болғанда ауыстырыңыз және сол күні жаңа мекенжаймен қосымшаның жаңа нұсқасын шығарыңыз (app/README.md).
  1. Жаңа доменнің A жазбасын серверге бағыттаңыз.
  2. `.env`-те мына жолдарды өзгертіңіз: `VITRINA_DOMAIN`, `VITRINA_CORS_ORIGINS`, `VITRINA_PUBLIC_API_URL` (қажет болса `VITRINA_TLS` та). `disk` режимінде `VITRINA_PUBLIC_MEDIA_URL`-ды да `https://ЖАҢА-ДОМЕН/media` етіңіз. `s3` режимінде оны өзгертпеңіз: фотолар бакетте қалады, сондықтан 3-қадамның орнына тек `sh /opt/vitrina/deploy/update.sh` іске қосыңыз.
  3. Фотолардың мекенжайын ауыстырыңыз (төмендегі «Фотоларды жаңа мекенжайға көшіру»). Ескі мекенжай: `https://ЕСКІ-ДОМЕН/media`.
  4. Соңында `https://ЖАҢА-ДОМЕН/api/v1/health` ашылып, `{"ok":true}` деп тұрғанын тексеріңіз.
- **`disk`-тен `s3`-ке көшу:**
  1. Бакеттерді дайындаңыз («Алдын ала керегі», 3-тармақ).
  2. `.env`-те `VITRINA_STORAGE=s3` қойып, S3 жолдарын толтырыңыз, ал `VITRINA_PUBLIC_MEDIA_URL` жолына фотолар бакетінің ашық мекенжайын жазыңыз.
  3. Бакеттерді тексеріңіз: `docker compose -f /opt/vitrina/deploy/compose.yml run --rm --no-deps api python -m vitrina_api.backup check`. Қате айтса, `.env`-ті түзетіп, қайталаңыз.
  4. Фотоларды көшіріңіз (төмендегі «Фотоларды жаңа мекенжайға көшіру»). Ескі мекенжай: `https://ДОМЕНІҢІЗ/media`. Файлдар көп болса, ұзақ көшіруді сайт жұмыс істеп тұрғанда алдын ала жасап қоюға болады: сондағы 1-қадамдағы командаға `--yes` орнына `--copy-only` жазыңыз.
  5. Бәрі ашылатынына көз жеткізген соң, дисктегі ескі файлдарды өшіріңіз. Олар әлі `https://ДОМЕН/media` арқылы ашылады, сондықтан сатушы өшірген фото да сол жерде қала береді: `docker compose -f /opt/vitrina/deploy/compose.yml run --rm --no-deps api sh -c 'rm -rf /data/media/* /data/private/*'`.

**Фотоларды жаңа мекенжайға көшіру.** Әр фотоның толық мекенжайы дерекқорда сақталған, сондықтан мекенжай ауысқанда (жаңа домен немесе S3) оларды ауыстыру керек. Бұл кезде сайт бірнеше минут жұмыс істемейді: сатушы мен сатып алушы ештеңе жазбауы керек. Командаларға фотолардың **ескі** мекенжайын жазыңыз:
```sh
C="docker compose -f /opt/vitrina/deploy/compose.yml"
sh /opt/vitrina/deploy/backup.sh                       # 1. алдымен көшірме
$C stop api photos jobs                                # 2. сайтты тоқтату
$C run --rm --no-deps api python -m vitrina_api.move_media https://ЕСКІ-ДОМЕН/media          # 3. не істейтінін көру
$C run --rm --no-deps api python -m vitrina_api.move_media https://ЕСКІ-ДОМЕН/media --yes    # 4. істеу
sh /opt/vitrina/deploy/update.sh                       # 5. сайтты жаңа баптаулармен қосу
```
- 3-команда ештеңені өзгертпейді. Ол қанша файлды көшіретінін және қанша мекенжайды ауыстыратынын көрсетеді.
- 4-команда істің өзін істейді:
  - `s3` режимінде алдымен жабық файлдарды, содан кейін фотоларды бакетке көшіреді. Бір файл көшпей қалса, бірде-бір мекенжай ауыспайды.
  - Бакеттегі фото құпия кілтсіз ашылмаса (бакет ашық емес немесе мекенжай қате), ештеңе өзгертпей тоқтайды.
  - Мекенжайларды бір транзакциямен ауыстырады: не бәрі ауысады, не ешқайсысы ауыспайды.
  - Жаңа мекенжай дерекқор бағанына сыймаса, тоқтайды.
  - Ескі мекенжай қате жазылса (мысалы `/media` ұмытылса), ештеңе өзгертпей тоқтайды және фотолар шын мәнінде қай мекенжайда тұрғанын жазады. Команданы сол мекенжаймен қайталаңыз.
- Команданы қайта іске қосуға болады: ол тек қалған жұмысты жасайды. Бәрі біткенде «nothing left to move» деп жазады.
- Қате болса, ештеңе өзгермейді: `sh /opt/vitrina/deploy/update.sh` сайтты қайта қосады. `.env`-ті бұрынғы күйіне қайтарсаңыз, сайт бұрынғыдай жұмыс істейді.
- **Құпия кілттер:** `.env` және `backup.env` файлдарының көшірмесін қауіпсіз жерде сақтаңыз, мысалы құпиясөз менеджерінде.

Production режимінде сервер қауіпсіз емес баптаумен іске қосылмайды. Мысалы, бакеттің бірі жоқ болса немесе мекенжай http болса, ол не түзету керегін журналға жазады: `docker compose logs api`.

**Аккаунтты қолдау арқылы жою.** `https://ДОМЕН/delete-account` беті қосымшаны аша алмайтын адамға `VITRINA_SUPPORT_CONTACT`-қа жазуды ұсынады. Алдымен сол нөмірге қоңырау шалып, сұрауды нөмір иесі жібергенін растаңыз, содан кейін:
```sh
cd /opt/vitrina/deploy
docker compose exec api python -m vitrina_api.delete_account +77010000000         # тек көрсетеді
docker compose exec api python -m vitrina_api.delete_account +77010000000 --yes   # жояды
```
Бұл қосымшадағы «Аккаунтты жою» батырмасымен бірдей қадамдарды жасайды. Ашық тапсырыс не төленбеген ақша болса, жоймай, себебін айтады.

**Бірінші әкімші.** Қолдау консолі (`https://ДОМЕН/admin`) тек әкімшіге ашылады. Ол адам алдымен қосымшаға бір рет кіруі керек, содан кейін:
```sh
cd /opt/vitrina/deploy
docker compose exec db psql -U vitrina -d vitrina -c "UPDATE users SET role='admin' WHERE phone='+77010000000'"
```

## Күнделікті жұмыс
Барлық команда `/opt/vitrina/deploy` қалтасынан орындалады.

| Не керек | Команда |
|---|---|
| Күйін көру | `docker compose ps` (бәрі `healthy` болуы керек) |
| Журнал | `docker compose logs -f --tail 100 api` (не `photos`, `jobs`, `caddy`) |
| Жаңа нұсқаны орнату | `sh update.sh` |
| Қайта іске қосу | `docker compose restart api` |
| Тоқтату / іске қосу | `docker compose down` / `docker compose up -d --wait` |
| Бакеттерді тексеру | `docker compose run --rm --no-deps api python -m vitrina_api.backup check` |

`update.sh` мына ретпен жұмыс істейді:
1. Кодты жаңартады (`git pull`).
2. Алдымен көшірме жасайды.
3. Жаңа образды жинайды. Осы уақытта ескі нұсқа жұмысын жалғастырады.
4. Фото процесі мен жұмыстар процесін тоқтатып, API-ге дерекқорды жаңартуға мүмкіндік береді.
5. Ескі образдарды өшіреді. Әйтпесе әр жаңарту дискіде ~200 МБ қалдырады.

Жаңа нұсқаға `.env`-те жоқ баптау керек болса (мысалы, SMS жолдары), скрипт оны `.env` соңына қосып, ештеңеге тимей тоқтайды. Бос жолды толтырып, `sh update.sh` командасын қайта орындаңыз.

Жаңа нұсқа іске қосылмаса, скрипт алдыңғы образға және жаңарту алдындағы дерекқорға қайтудың дайын командаларын шығарады.

Журналдардың көлемі шектелген: әр қызметке 5 × 10 МБ. Диск 90%-дан асса, түнгі көшірме мұны қате ретінде хабарлайды.

## Резервтік көшірме
- Көшірме әр түні 02:30–02:40 аралығында (Қазақстан уақыты) жасалады, оны `vitrina-backup.timer` іске қосады.
- Дерекқор сақталатын жерлер:
  - `/var/backups/vitrina` қалтасына, соңғы 7 күндікі;
  - көшірме бакеті болса, соған да, соңғы 30 көшірме.
- `disk` режимінде фотолар мен жабық файлдардың көшірмесі `/var/backups/vitrina/files` қалтасына жасалады. Ол қалта әр түні дискідегі қалталармен бірдей болады: жаңа файлдар қосылады, ал дискіден өшірілген файлдар `files/removed/КҮН/` қалтасына жылжиды және сонда 30 күн сақталады.
- Әр көшірменің жанында SHA-256 қосындысы тұрады. Қалпына келтіру оны тексереді, сондықтан соңы кесілген көшірме қабылданбайды.
- Атауындағы кездейсоқ бөлік көшірмені уақыты бойынша табуға мүмкіндік бермейді.
- Бакет ашық болса, көшірме жасалмайды, ал скрипт қатемен аяқталады.
- `s3` режимінде фотолар бұл көшірмеге кірмейді. Фотолар бакетінің нұсқаларын (versioning) провайдердің өзінде қосыңыз.

**Серверден тыс көшірме (`disk` режимі, көшірме бакеті жоқ).** Бұл жағдайда барлық көшірме сол серверде тұрады. Сервер не оның дискі жоғалса, бәрі жоғалады. Түнгі скрипт әр жолы «no backup bucket» деп ескертеді. `/var/backups/vitrina` қалтасын жиі, мысалы аптасына бір рет, өз компьютеріңізге көшіріп тұрыңыз:
```sh
rsync -a --link-dest=../latest root@SERVER_IP:/var/backups/vitrina/ ~/vitrina-backups/$(date +%F)/ && ln -sfn $(date +%F) ~/vitrina-backups/latest
```
Әр көшіру жаңа күн қалтасына түседі, ал өзгермеген файлдар алдыңғы қалтамен ортақ болады (hard link), сондықтан орын аз алады. Серверде бірдеңе өшірілсе, ескі қалталарда ол сақталып қалады. Ескі күн қалталарын өзіңіз өшіресіз.
Онда телефон нөмірлері, мекенжайлар және түбіртектер бар. Оны шифрланған дискте сақтаңыз.

**`deploy/backup.env` файлы.** Оны тек көшірме скрипттері оқиды, сайттың өзі оқымайды. Онда екі баптау бар:
- `VITRINA_S3_BACKUP_ACCESS_KEY` және `VITRINA_S3_BACKUP_SECRET_KEY`: тек көшірме бакетіне арналған кілт.
  - Бұл кілтті қолдансаңыз, `.env`-тегі негізгі кілттен көшірме бакетіне рұқсатты алыңыз.
  - Сонда сайт бұзылса да, көшірмелерді өшіру мүмкін болмайды.
- `VITRINA_BACKUP_PING_URL`: әр сәтті көшірмеден кейін шақырылатын мекенжай, сәтсіз көшірмеден кейін `…/fail` шақырылады.
  - Мысалы, healthchecks.io-дағы тегін тексеру. Шақыру келмей қалса, ол email жібереді.
  - **Бұл мекенжайсыз көшірме тоқтап қалғанын ешкім білмейді.**

```sh
sh backup.sh                                     # қазір көшірме жасау
systemctl list-timers vitrina-backup.timer        # соңғы және келесі іске қосылу уақыты
journalctl -u vitrina-backup -n 30               # соңғы көшірме кезінде не жазылды
docker compose run --rm --no-deps api python -m vitrina_api.backup list   # бакеттегі көшірмелер
```

### Қалпына келтіру
Қалпына келтіру бүкіл дерекқорды көшірмемен ауыстырады. Ол бір-екі минут алады, осы уақытта сайт 502 деп жауап береді.

Скрипт алдымен көшірменің бүтін екенін тексереді. Бүтін болмаса, ештеңе өзгермейді. Содан кейін қазіргі дерекқорды `before-restore-….dump` файлына сақтайды, сондықтан қалпына келтіруді де кері қайтаруға болады. Ол файлдар 30 күннен кейін өшіріледі.
```sh
sh restore.sh /var/backups/vitrina/vitrina-20261020T213000Z-3f9a0c1d.dump --yes
sh restore.sh --from-bucket vitrina-20261020T213000Z-3f9a0c1d.dump --yes      # бакеттен
sh restore.sh --files --yes      # disk: фотолар мен жабық файлдарды /var/backups/vitrina/files-тан қайтару
```
`--files` бар файлдарды өшірмейді. Ол тек жоқ не өзгерген файлдарды көшірмеден қайтарады.
Домен немесе фото сақтау орны ауысқаннан бұрын жасалған көшірмені қалпына келтірсеңіз, ондағы фотолар ескі мекенжаймен жазылған. Содан кейін «Фотоларды жаңа мекенжайға көшіру» командаларын қайта орындаңыз.
Қалпына келтіру ортасында құласа, API тоқтап тұрады. Скрипт бұрынғы дерекқорға қайтаратын дайын команданы шығарады.

### Жаңа серверге көшу
1. Жаңа серверде `git clone` жасаңыз. `setup.sh` іске қосылмай тұрып, ескі `.env` пен `backup.env` файлдарын `/opt/vitrina/deploy/` қалтасына көшіріңіз. Содан кейін `sh /opt/vitrina/deploy/setup.sh` командасын дәлелсіз (аргументсіз) іске қосыңыз. Бұл ретті сақтау керек: `setup.sh` бірінші болып іске қосылса, дерекқор жаңа құпиясөзбен жасалады.
2. Ескі серверде сайтты тоқтатып, соңғы көшірмені жасаңыз:
   ```sh
   docker compose stop api photos jobs && systemctl disable --now vitrina-backup.timer && sh backup.sh
   ```
3. Жаңа серверде сол көшірмені қалпына келтіріңіз:
   - `disk` режимінде (бакет болса да, болмаса да) алдымен ескі сервердің көшірмелер қалтасын жаңа серверге көшіріңіз: `rsync -a root@ЕСКІ_IP:/var/backups/vitrina/ /var/backups/vitrina/`. Фотолар тек осы қалтада.
   - Дерекқорды қалпына келтіріңіз. Ескі сервер 2-қадамда шығарған атауды (`backup done: АТАУ`) пайдаланыңыз, себебі жаңа сервердің өз бос көшірмесі одан да жаңа: `sh restore.sh /var/backups/vitrina/АТАУ --yes`, ал бакеттен болса `sh restore.sh --from-bucket АТАУ --yes`.
   - `disk` режимінде файлдарды қайтарыңыз: `sh restore.sh --files --yes`.
4. Доменнің A жазбасын жаңа серверге бағыттап, `docker compose restart caddy` командасын орындаңыз.

## Қосымша (APK)
Google Play-ге арналған нұсқаны GitHub Actions-тағы **Store release** жинайды: жүктеу кілтін құпиялардан алып, сервер мекенжайын тексереді ([app/README.md](../app/README.md)). Кілтсіз сынап көру үшін:
```sh
cd app && flutter build apk --release --dart-define=API_BASE=https://vitrina.kz/api/v1
```
- Let's Encrypt сертификатын Android 7.0 және одан ескі телефондар танымайды. Оларда қосымша «байланыс жоқ» деп көрсетеді. Мұндай телефондар аз, бірақ қосымша оларда да орнатылады. Оларды Play Store-да өшіру үшін `minSdk = 25` қойыңыз.

## Әлі жоқ: іске қоспас бұрын шешу керек
- **SMS шектері.** Бір IP мекенжайдан сағатына 120 код сұрауға болады, себебі мобильді операторларда көп телефон бір мекенжайды бөліседі (CGNAT). Бір нөмірге қайта жіберу 60 секундтан кейін ғана. Аккаунты жоқ жаңа нөмірлерге тәулігіне ең көбі 2000 SMS (`VITRINA_SMS_PER_DAY`): біреу нөмірлерді ауыстырып жатса да, баланс таусылмайды. Шекке жеткенде тек жаңа тіркелу тоқтайды, бұрыннан бар пайдаланушылар кіре береді. Тіркелу көбейсе, бұл санды көтеріңіз.
- **SMS-ті бақылау.** Баланс бітсе, Mobizon істемесе не шекке жетсе, бұл тек API журналына жазылады (`docker compose logs api | grep sms`), ешкімге хабар келмейді. Mobizon-ның өзінде балансы аз болғанда хабарлайтын баптау болса, қосып қойыңыз.
- **Төлем және жеткізу.** Лицензиясы бар төлем серіктесі жоқ, сондықтан сервер `VITRINA_PAYMENTS=off` режимінде ғана іске қосылады: тапсырыс пен баға ұсынысы қабылданбайды, ал қосымшада «Тапсырыс беру» орнына «Сатушыға жазу» шығады. Сатып алушы мен сатушы чатта келіседі, ақша сайт арқылы өтпейді.
  - Нақты провайдерді қосу үшін бағдарламалау жұмысы керек: оның төлем беті мен webhook қолтаңбасының пішімі. Содан кейін ғана `VITRINA_PAYMENTS` қосылады.
  - `.env`-тегі `VITRINA_PAYMENT_SECRET` пен `VITRINA_DELIVERY_SECRET` тек сынақ webhook-тарына арналған.
- **Сайттың өзін бақылау.** Сайт құласа, ешкім хабар алмайды. Сыртқы тексеру (uptime) қызметін `https://ДОМЕН/api/v1/health` мекенжайына қосқан дұрыс.
- **IPv6.** Серверде IPv6 болса, IPv6 арқылы келетін клиенттер API-ге бір мекенжаймен көрінеді. Олар кіру шектеуін бөлісуі мүмкін. Орнатқаннан кейін тексеру керек.

## Тексеру
`deploy/test/smoke.sh` скрипті CI-де әр push сайын GitHub-тың таза Ubuntu машинасында іске қосылады. Ол мыналарды жасайды:
- `setup.sh`-тың өзін іске қосады: пакеттер, брандмауэр, уақыт белдеуі, түнгі көшірме таймері және оның бір рет іске қосылуы;
- осы `compose.yml`-ді екі рет іске қосады: фотолар дискте (`disk`) және S3-тің орнын басатын сынақ қызметінде (`s3`), уақытша сертификатпен;
- HTTPS-ті және http-тен бұруды тексереді;
- сырттан тек Caddy-ге жетуге болатынын тексереді;
- сатушының фотомен тауар қосуын және фото процесінің жұмысын тексереді;
- бөлісу бетіндегі https мекенжайды тексереді;
- production тексерісін және бакеттерді тексеруді тексереді;
- көшірме жасап, оны қалпына келтіреді (`s3`: бакеттен; `disk`: дискіден, сонымен бірге жоғалған фотоны файлдар көшірмесінен);
- `disk` режимінде фотоны Caddy беретінін, ұзақ кэш және `nosniff` тақырыптарын тексереді;
- жартылай және соңы кесілген көшірмелердің қабылданбайтынын тексереді;
- `update.sh` жаңартуын тексереді.

Нақты hoster.kz серверінде және нақты доменмен әлі тексерілген жоқ.
