# VITRINA-ны серверге орнату

Бұл нұсқаулық таза Ubuntu 22.04 не 24.04 серверіне арналған (2 ядро, 4 ГБ жад жеткілікті). Серверде бәрі Docker-де жүреді:

| Қызмет | Не істейді |
|---|---|
| `caddy` | Интернетке ашық жалғыз қызмет (80 және 443 порттары). Доменге HTTPS сертификатын Let's Encrypt-тен өзі алып, өзі жаңартады. http сұрауларын https-ке бұрады. |
| `api` | Сервер, 2 процесс (бір ядроға бір процесс). Жаңа нұсқа іске қосылғанда дерекқорды өзі жаңартады (`alembic upgrade head`). |
| `photos` | Фотолардың фонын алады, кіші көшірмелерін және іздеу векторын жасайды. Ең көбі 1,7 ГБ жад алады (өлшенген), шегі 2,5 ГБ. |
| `jobs` | Әр 5 минут сайын уақытқа байланысты жұмыстарды орындайды: төленбеген тапсырыстарды жабу, ақшаны қайтару, тапсырысты өзі аяқтау, еске салу. |
| `db` | PostgreSQL 16. Порты ашық емес, оған тек ішкі қызметтер жетеді. |

Фотолар серверде сақталмайды. Олар S3-үйлесімді сақтау орнында тұрады, телефондар оларды тікелей сол жерден жүктейді.

## Алдын ала керегі
1. **Сервер**: Ubuntu 22.04 не 24.04, root арқылы SSH кіру.
2. **Домен**: оның A жазбасы сервердің IP-іне бағытталуы керек, мысалы `vitrina.kz → 203.0.113.10`. Сертификат тек содан кейін алынады.
3. **S3-үйлесімді сақтау орны**: бір endpoint, бір кілт жұбы және үш бакет.
   - `vitrina-photos`: фотолар, **ашық оқу** рұқсатымен.
   - `vitrina-private`: түбіртектер мен дау дәлелдері, ашық **емес**.
   - `vitrina-backup`: дерекқордың түнгі көшірмелері, ашық **емес**.
4. **Let's Encrypt үшін email**: сертификат туралы хаттар соған келеді.

## Орнату
```sh
ssh root@SERVER_IP
apt-get update && apt-get install -y git
git clone -b claude/initial-code https://github.com/ooik2086-cmd/vitrina /opt/vitrina
sh /opt/vitrina/deploy/setup.sh vitrina.kz you@example.kz
```
Бірінші іске қосуда скрипт мыналарды жасайды:
- Docker-ді орнатады;
- брандмауэрді қосады: тек ssh, 80 және 443 порттары ашық қалады;
- 2 ГБ swap қосады;
- қауіпсіздік жаңартуларын автоматты түрде қосады;
- жаңа кездейсоқ құпия кілттермен `deploy/.env` файлын жазады.

Содан кейін скрипт тоқтап, қай жолдарды толтыру керегін көрсетеді. Ол жолдар S3 бөлімінде:
```sh
nano /opt/vitrina/deploy/.env
```
Толтырған соң скриптті қайта іске қосыңыз:
```sh
sh /opt/vitrina/deploy/setup.sh
```
Скрипт сайтты іске қосып, `https://ДОМЕН/api/v1/health` мекенжайын тексереді. Жауап `{"ok":true}` болуы керек.

`.env` файлының көшірмесін қауіпсіз жерде сақтаңыз, мысалы құпиясөз менеджерінде. Скрипт бар `.env` файлын ешқашан қайта жазбайды.

Production режимінде сервер қауіпсіз емес баптаумен іске қосылмайды. Мысалы, бакеттің бірі жоқ болса немесе http мекенжай берілсе, ол не түзету керегін журналға жазады:
```sh
cd /opt/vitrina/deploy && docker compose logs api
```

## Күнделікті жұмыс
Барлық команда `/opt/vitrina/deploy` қалтасынан орындалады.

| Не керек | Команда |
|---|---|
| Күйін көру | `docker compose ps` (барлығы `healthy` не `running` болуы керек) |
| Журнал | `docker compose logs -f --tail 100 api` (не `photos`, `caddy`) |
| Жаңа нұсқаны орнату | `git pull && docker compose up -d --build --wait` |
| Қайта іске қосу | `docker compose restart api` |
| Тоқтату / іске қосу | `docker compose down` / `docker compose up -d --wait` |

Журналдардың көлемі шектелген: әр қызметке 5 × 10 МБ.

## Резервтік көшірме
- Көшірме әр түні 02:30-да (Қазақстан уақыты) жасалады, оны `vitrina-backup.timer` іске қосады.
- Дерекқор екі жерге сақталады:
  - `/var/backups/vitrina` қалтасына, соңғы 7 күндікі;
  - `vitrina-backup` бакетіне, соңғы 30 көшірме. Әр көшірменің жанында SHA-256 қосындысы тұрады.
- Сервер мүлдем жоғалса, бакеттегі көшірме қалады.
- Фотолар бұл көшірмеге кірмейді, олар бакетте сақталады. Фотолар бакетінің көшірмесін немесе нұсқаларын (versioning) провайдердің өзінде қосыңыз.

```sh
sh backup.sh                                     # қазір көшірме жасау
systemctl list-timers vitrina-backup.timer        # соңғы және келесі іске қосылу уақыты
journalctl -u vitrina-backup --since today        # көшірме жасалғанда не жазылды
docker compose run --rm --no-deps api python -m vitrina_api.backup list   # бакеттегі көшірмелер
```

### Қалпына келтіру
Қалпына келтіру бүкіл дерекқорды көшірмемен ауыстырады. Ол бір-екі минут алады, осы уақытта сайт 502 деп жауап береді. Скрипт алдымен қазіргі дерекқорды `before-restore-….dump` файлына сақтайды, сондықтан қалпына келтіруді де кері қайтаруға болады.
```sh
sh restore.sh /var/backups/vitrina/vitrina-20261020T213000Z.dump --yes
sh restore.sh --from-bucket vitrina-20261020T213000Z.dump --yes      # бакеттен
```
**Жаңа серверге көшу:**
1. Жоғарыдағыдай орнатыңыз, бірақ сақтап қойған ескі `.env` файлын пайдаланыңыз.
2. `restore.sh --from-bucket …` арқылы соңғы көшірмені қалпына келтіріңіз.
3. Доменнің A жазбасын жаңа серверге бағыттаңыз.

## Қосымша (APK)
Нақты серверге қосылатын APK былай жиналады:
```sh
cd app && flutter build apk --release --dart-define=API_BASE=https://vitrina.kz/api/v1
```
Play Store үшін қолтаңба кілті (upload key) керек. Бұл әлі бапталмаған.

## Әлі жоқ: іске қоспас бұрын шешу керек
- **SMS провайдері.** Production-да кіру коды жауапта қайтарылмайды, ал SMS жіберетін провайдер әлі қосылмаған. Сондықтан провайдер қосылғанша сайтқа ешкім кіре алмайды.
- **Төлем және жеткізу серіктестері.** Олардың webhook кілттері (`VITRINA_PAYMENT_SECRET`, `VITRINA_DELIVERY_SECRET`) `.env`-те дайын тұр. Келісім жасалғанда серіктеске осы кілттер беріледі.
- **Мониторинг.** Сервер не көшірме тоқтап қалса, ешкім хабар алмайды. Сыртқы тексеруді (uptime) `https://ДОМЕН/api/v1/health` мекенжайына қосқан дұрыс.

## Тексеру
`deploy/test/smoke.sh` мына жұмыстарды тексереді. CI оны әр push сайын іске қосады:
- осы `compose.yml`-ді S3-тің орнын басатын сынақ қызметімен және уақытша сертификатпен іске қосады;
- HTTPS-ті және http-тен бұруды тексереді;
- сырттан тек Caddy-ге ғана жетуге болатынын тексереді;
- сатушының фотомен тауар қосуын және фото процесінің жұмысын тексереді;
- бөлісу бетіндегі https мекенжайды тексереді;
- production тексерісін тексереді;
- көшірме жасап, оны бакеттен қалпына келтіреді.

`setup.sh` скриптінің өзі (Docker орнату, брандмауэр, swap, таймер) нақты таза серверде әлі іске қосылып көрген жоқ.
